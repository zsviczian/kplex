# K-Plex architecture

This records the boundary being built by the [refactor plan](../Refactor%20plan.md). E00 adds the first production presentation seam under `src/core/contracts/`, `src/core/plex/` and `src/adapters/obsidian/`; the graph, indexing, lens and most UI runtime still live in the legacy paths. A passing architecture check proves only the migrated roots and their reachable imports are host-clean, not that the remaining graph or UI is host-independent.

```mermaid
flowchart TB
  main["Obsidian main.ts / composition"] --> host["adapters/obsidian"]
  main --> app["application"]
  main --> features["ui/features"]
  host --> app
  host --> graph["core/graph"]
  features --> app
  features --> plex["core/plex"]
  features --> components["ui/components"]
  app --> plex
  app --> graph
  plex --> graph
  graph --> contracts["core/contracts"]
  features --> lang["lang"]
  host --> lang
```

Arrows mean **may import**, not call direction. A capability interface belongs in the lowest layer that needs it. For example, an application navigation port is defined by application code and implemented by the Obsidian adapter; application code does not import that adapter. React feature content may use a graph read contract but may not classify relationships again. Portable components may use React and standard DOM APIs but not Obsidian, domain policy or plugin state.

| Layer | Owns | May depend on |
| --- | --- | --- |
| `src/lang/` | English source catalog and host-free typed lookup/formatting | Lang only |
| `src/core/contracts/` | Small shared host-free values when actually needed | Itself |
| `src/core/parser/` | Plain Markdown/property grammar, parser DTOs and injected cooperative parsing | Parser only |
| `src/core/graph/` | Identities, evidence, source compilation, relationship meaning, queries | Graph and contracts |
| `src/core/plex/` | Projection policy, predicates, pure layout strategies and semantic-to-physical gate mapping | Plex, graph and contracts |
| `src/application/` | Use cases, revisions, intent coordination and narrow host ports | Application and core |
| `src/ui/components/` | Domain-independent React interaction mechanics | Components, React and ReactDOM |
| `src/ui/features/` | Portable feature presentation | Features, components, application, core, lang, React and ReactDOM |
| `src/adapters/obsidian/` | Vault/source collection, writes, storage, native shells and lifecycle binding | Other layers, lang and Obsidian |
| `src/main.ts` | Plugin lifecycle and composition | Other layers and Obsidian |

The checker walks static imports and re-exports, type-only imports, literal `import()` types, literal dynamic imports and `require()` calls, resolving aliases through `tsconfig.json`. It rejects unresolved/nonliteral loading, forbidden host imports/globals, Obsidian DOM helper calls and wrong-direction edges in migrated layers. A portable root cannot import an unmigrated legacy file: migrate or introduce a narrow host-free contract first. Adapter-to-core imports are allowed. New layer cycles fail. The real `npm run build` remains necessary for full TypeScript and Obsidian-type validation; the checker does not prove runtime portability, behavior or a working second host.

No grandfathered migrated edges exist. E00 contributes four migrated production roots: the host-free presentation contract, pure routing/profile policy, pure Obsidian fact classifier and Obsidian presentation adapter. Legacy `src/index/`, `src/lens/`, most of `src/ui/` and `src/settings.ts` still have Obsidian coupling. `src/ui/viewProfile.ts` is a compatibility facade over the migrated profile selector and is intended to retire with the remaining migration facades at C25. C03–C05 migrate UI mechanics; C08–C20 migrate graph, application and Plex contracts; C21–C24 move intent and host shells. Record any temporary exact-edge exception with its reason and retirement checkpoint before adding it; the current checker has no such exception mechanism.

| New feature | First owner and check |
| --- | --- |
| Relationship source or ontology rule | Obsidian adapter collects facts; graph compiler/resolver owns meaning and evidence. Compare canonical declarations and decisions. |
| Shared URL referrers | Source records preserve each declaring note for one URL identity; graph read contracts retain all relationships. Showing multiple referrers around a centered URL is [feature request #26](https://github.com/zsviczian/kplex/issues/26), outside refactor scope. |
| Search or lens operator | Graph read/query or Plex predicate contract; preserve ranking/filter ordering and lazy property reads. |
| Condensed, expanded, rotated or mindmap view | Projection policy decides included semantic nodes; layout strategy maps roles to positions/gates. Mode changes must not rebuild graph semantics. |
| Toolbar action or modal | Portable component/feature for reusable interaction, application intent for action, native shell for Obsidian workspace or Vault effects. |
| Device-dependent action or shortcut hint | Host adapter supplies device/input/OS facts and available actions; portable presentation selects applicable affordances and formats catalog copy from the actual shortcut. |
| Another PKM host | A new adapter implements existing narrow ports and supplies normalized facts; no host-specific parsing of opaque core IDs. |

The localization boundary now has an English source catalog and typed translator under `src/lang/`. `src/adapters/obsidian/localization.ts` reads the host language with Obsidian's typed `getLanguage()` export and constructs the translator; missing locales/keys fall back to English. Portable feature presentation can receive/use the translator without importing Obsidian. Core graph semantics do not import UI translations. L00 migrates only representative production copy; L01 will enforce catalog use for all remaining plugin-owned user-facing copy. Console diagnostics remain English, and no non-English translation is part of this refactor.

The environment boundary is established by E00. `src/core/contracts/presentationEnvironment.ts` defines host-free device, key-convention, input-mode and host-action facts; `src/core/plex/viewPresentation.ts` owns pure command/routing decisions and the explicit `phone` → persisted `mobile` layout-key mapping. `src/adapters/obsidian/presentationEnvironmentFacts.ts` holds the pure Obsidian flag/viewport classifier, and `src/adapters/obsidian/presentationEnvironment.ts` reads those facts at the host boundary. `src/main.ts` composes a fresh environment when routing commands/views or selecting profiles, so there is no process-wide mutable platform singleton. Existing desktop/tablet/phone command and layout behavior remains the production policy, while graph semantics, indexing and iOS memory policy stay outside this presentation contract. Mobile keyboard presence is reported as `unknown` when the host cannot detect an attached keyboard; future shortcut hints must not treat that as a confirmed absence. L00 pairs catalog copy with `src/core/plex/shortcutPresentation.ts`, which formats the actual shortcut convention, such as Command/Option on macOS or Control/Alt on Windows. A future host supplies its own environment facts and available actions. Device class does not imply keyboard, pointer, touch or pop-out support; physical phone/tablet checks remain separate from desktop emulation.

Run `npm run verify` before review. It runs architecture self-tests/checker, the restricted host-free core type/runtime lane, official Obsidian ESLint, the aggregate behavioral tests and the production build. `npm run verify:obsidian` is a separate, strict, explicitly configured exact-build test-vault lane; it is not part of portable CI.

## C08 graph contracts

`src/core/graph/model.ts` introduces an exact opaque `NodeId` and a readonly `GraphNodeView` with explicit kind/resolution and optional plain file metadata. Core must not infer paths, case rules or kind from an ID. `src/core/graph/settings.ts` describes only the values used by today's legacy semantic-index signature; presentation metadata still present in that signature is separated in C18 rather than reinterpreted in C08.

`src/adapters/obsidian/graphContracts.ts` maps a legacy `GraphPage` or settings object at the host boundary. Mapping one node is bounded: it creates a small view/file facet and shares existing metadata arrays through readonly types. These types do not freeze legacy data. C09 binds its first production consumer to the existing publication/presentation revision; legacy graph identity, settings persistence and snapshot schemas remain authoritative and unchanged. `check:core` covers all core `.ts`/`.tsx` files with ES2021 only and no DOM/Node ambient types; clean-process runtime tests exercise opaque IDs, while adapter tests cover every legacy node kind and the narrow settings mapping.

## C09 first graph read port: search

C09 introduces `src/core/graph/read.ts` with the deliberately narrow `GraphSearchRead` capability. Its production consumer is `src/ui/features/SearchBox.tsx` (the old `src/ui/SearchBox.tsx` path is a compatibility re-export): the search box now receives ranked `GraphSearchHit` values containing an opaque `NodeId`, a plain `GraphNodeView`, and the already-resolved display label and secondary caption. Secondary captions come from the adapter; the consumer never interprets opaque IDs as paths. It no longer imports `GraphIndex`, `GraphPage`, `TFile`, plugin state, or mutable neighbour maps. `App` injects the native search icon and existing portal/topbar selectors; the feature renders the portable `FuzzySuggester` directly, avoiding a transitive Obsidian import through the legacy input wrapper. Architecture checks and an actual browser consumer test cover this dependency boundary. Search ranking, visibility, entry-point ordering, prefix caching, configured display-name policy, and the search index itself remain owned by the legacy `GraphIndex`; C17 is responsible for extracting search semantics later.

`createLegacyGraphSearchRead()` in `src/adapters/obsidian/graphContracts.ts` is the compatibility boundary. It delegates each query to the existing `GraphIndex.search()`/`titleFor()` behavior and maps only returned pages through the C08 node-view mapper. It does not copy/cache the vault or create a second graph. Metadata arrays remain readonly shared references, so a hit is **not a frozen snapshot**: mapped hits are valid for the publication/presentation revision in which `search()` ran. `App` passes its existing index `renderRevision` to `SearchBox`; full/preview publication, incremental commits, rename/delete, optimistic index notifications, and display-name refresh already emit through that boundary, causing the search box to query again. Activation crosses back into legacy composition by resolving only the opaque ID with `GraphIndex.get()` immediately before the existing navigation callback.

This is intentionally not a general graph API. `layout.ts`, `PlexGraph.tsx`, `PlexFilter.tsx`, `ContentPane.tsx`, legacy lens composition, relationship explanation/evidence, and other navigation/search callers still consume the concrete legacy index or legacy graph pages. The actual predicate/parser/lens evaluation is now portable under C10. Neighborhood and evidence ports should be added only when a real later consumer is migrated; presentation-filtered `neighbours()` must not be mislabeled as raw semantic adjacency. C10 owns lazy property/predicate extraction and C17 owns search implementation extraction.

## C10 portable predicate and lens runtime

C10 moves predicate execution into `src/core/plex/predicate.ts` and include/exclude/style/evidence composition into `src/core/plex/lens.ts`. The core sees only `GraphNodeView`, explicit semantic/file paths, plain edge/evidence records, a field-at-a-time `GraphPropertyProvider`, and a pair-scoped `GraphEvidenceProvider`. It has no Obsidian, `GraphIndex`, `GraphPage`, `TFile`, plugin, window, or mutable-neighbour dependency. Plain file facets carry physical mtime/basename/ctime/size; explicit node mtime retains semantic page time, including null on unbacked nodes. `node.path`, `file.path` and `this.path` selectors preserve the legacy semantic path, independently of the physical file path. Raw edge relationType/linkDirection selector values retain their numeric representation; kind/direction selectors retain their descriptive strings.

`src/core/plex/predicateParser.ts` owns the unchanged grammar; the legacy parser path is a re-export. `src/lens/GraphPredicate.ts` remains a compatibility delegate for current PlexGraph callers. `src/adapters/obsidian/predicateContracts.ts` owns its cached-property provider, plain context/candidate mapping and bounded evidence provider; it uses the public file lookup for a requested Markdown field and never reads bodies. `src/lens/GraphLens.ts` retains persisted-definition validation/style sanitation but delegates runtime matching/style composition to core through typed adapters, without unchecked double casts. Evidence mapping calls `explainRelationship()` only for evidence-scope candidates and copies plain decision records. Idle/null/style-only visibility paths avoid needless candidate mapping. Parser/AST evaluation has one implementation; Simple builders still compose through compatibility exports. This is intentionally not a generic graph API. C19/C24 own later retirement of the legacy candidate/composition facades. Existing `App` metadata-cache notifications increment only the predicate presentation revision for visible views; they do not request a semantic rebuild, while hidden mounted views catch up through their normal reveal/render path.

C09 acceptance evidence is in [C09 validation](validation/C09-2026-09-26.md). Open queries refresh after publication without losing focus. Deletion preserves legacy materialization semantics: a deleted file becomes a searchable unresolved placeholder when placeholders are enabled; hiding placeholders removes it from the result list. The read port does not change that policy.

C10 acceptance evidence is in [C10 validation](validation/C10-2026-09-26.md): restricted/clean-process checks, prior-evaluator comparisons and exact-build large-vault property/lens/evidence/layout assertions passed. No production indexing, persisted formats, grammar, native UI mechanics or responsive routing changed.

## C11 normalized source contract

`src/core/graph/source.ts` defines the host-free normalized source vocabulary used by later C12/C13 work. C11 has **no production consumer**: the existing `GraphBuilder`/`RelationEvidence`/`RelationResolver` pipeline remains authoritative. The contract keeps opaque node identity independent from semantic/physical paths and materialization state, preserves typed source occurrences/provenance and exact producer-selected targets, and deliberately omits relationship role/type/direction/precedence. Explicit contribution owners retain per-note ownership for tag membership; metadata surfaces and name-only field-discovery facts preserve later precedence/discovery inputs. Malformed URLs retain their node with no origin fact. Host link resolution, Date-property/Daily Notes normalization and presentation-link counting stay producer/adapter responsibilities; semantic classification stays graph-owned.

Source iteration is a bounded sequence of at most 256 records per batch. A dense file may span many batches; the contract has no per-file occurrence array. This is a record-count bound, not a payload-byte/memory guarantee; C12 must retain byte budgets and avoid repeated dense-value copying. Test-only fixture producers materialize tiny arrays; production must not add a second full-vault DTO. Opaque per-source revisions are separate from coherent whole-read generation/snapshot tokens. Batch sequence is the validity/ordering token within a coherent boundary; changed batch content requires a new boundary. The small contract-seam helpers reject mixed/stale generations and allow publication only after a final sequential batch whose read boundary is still current. They are not a production scheduler or publisher.

The complete current-family mapping, provenance availability, URL-origin derivation, image-only reconciliation facts, fixture strategy and C12 adoption order are documented in [Normalized source contract](NORMALIZED_SOURCE_CONTRACT.md). `tests/normalized-source-contract.test.mjs` compiles the contract into a clean Node process with no Obsidian/window shim, produces records from the existing compatibility Markdown fixture, compares direct-family multiplicity with the legacy graph golden, and exercises a separate opaque/source-relative/shared-URL fixture. Production C12 adapters now consume this contract across every existing semantic source family.

## C12a production structural collection

`ObsidianStructuralSourceCollector` now owns full-build Vault tree and cached tag reads. It emits bounded C11 records; the legacy `GraphBuilder` consumes them to create pages and evidence using its existing semantics. File facts carry exact semantic/physical paths and file facets. `materializedFile()` rebinds a plain facet through the host for the transitional `GraphPage.file` reference. The real Obsidian root is `/` with an empty host name; its semantic page retains the existing `/` display label.

Tag records preserve raw host spelling. The legacy compiler's `ensureTagPath()` still owns normalization, exclusions, hierarchy construction and deduplication; a run-local map resolves each raw tag once and retains only existing graph page references, not lists of members. Raw tag source IDs are transitional collector identities, not a replacement for canonical `tag:` graph identities. Note-owned contribution revisions distinguish physical membership input from the tag declaring the relation. Full metadata enrichment already skips tag attachment; incremental tag collection remains legacy for C14. Raw repeated memberships retain their original declaration multiplicity; only hierarchy edges are deduplicated.

Collection accepts at most 256 records per batch and allows a file-tree target fact to arrive later. The present structural emitter sends each relationship adjacent to its entity, so unresolved structural references are short-lived; the generic C11 contract alone does not bound arbitrary compiler deferral. Finalization compares a second structural/tag digest without constructing discarded DTOs, and fences both scans with the existing plugin source-event revision. `getIndexSourceRevision()` is a narrow compatibility accessor over the existing dirty revision, with coordination ownership moving in C15; it creates no new scheduler or subscription. Rejected/reentrant/cancelled collection cannot finalize or replay. The collector owns no timers/listeners/storage and expires with its build.

At C12a acceptance, the remaining families stayed on their existing owners. C12b/C12c subsequently migrated link, ontology and metadata facts; parsing/cache reads and incremental publication still have C13/C14/C16 owners. Current GraphIndex/coordinator publication and follow-up semantics are unchanged; C12a is not a full latest-wins publisher or a host-free compiler.

## C12b production host-link and ontology collection

`ObsidianHostLinkSourceCollector` owns production reads of Obsidian's aggregate `resolvedLinks` and `unresolvedLinks` maps for both full rebuilds and source-scoped incremental patches. Each normalized record preserves the exact source/target map identity and host occurrence count. Resolved endpoints carry the exact materialized file path/kind selected by the host map; unresolved endpoints remain explicit unresolved semantic identities. Aggregate maps do not expose literal Markdown spelling, headings or physical locations, so the adapter does not invent them. Whole-map collection streams source/target entries directly, caps every normalized batch at 256 records, checkpoints cooperatively and verifies the family digest a second time before finality. The same existing monotonic source-event revision fences both scans. Semantic no-op fingerprints use the adapter's count-bearing map reader rather than a second GraphBuilder-owned host-map read.

`ObsidianOntologySourceCollector` receives the already merged per-file metadata view from the existing parser/cache path. It selects only configured ontology fields, emits frontmatter/inline `OntologyOccurrence` facts and owns source-relative `getFirstLinkpathDest()` resolution. Literal raw targets, heading/block subpaths, configured field identity, physical inline field spelling, raw values and inline line/start/end provenance remain separate facts. The shared property-value link grammar now has a streaming iterator so dense values can feed bounded normalized batches without first materializing a target array; the compatibility `extractLinksFromValue()` wrapper remains for legacy imagery/section/editing consumers, while C12c consumes normalized presentation references. Per-file collection fences the source-event revision plus file path/mtime/size across async checkpoints.

`GraphBuilder` remains the only semantic compiler. It maps configured ontology fields to the existing hierarchy roles, preserves duplicate assignments across multiple configured role groups, applies self/index exclusions through the existing evidence helpers, creates existing virtual/URL targets and leaves precedence/inverse resolution in `RelationResolver`. Full rebuild and incremental patch paths use the same host-link/ontology adapters; staging/publication policy is unchanged and remains C14/C15 work. Host-link counts are retained as source facts even though the current compiler intentionally creates one generic inferred declaration per source/target summary, matching legacy behavior.

C12c moves the final graph-construction `resolvedLinks` read into a demand-only source/visual-target adapter service; GraphBuilder retains no whole-vault count copy. The compatibility `extractLinksFromValue()` resolver also remains outside C12b where it serves presentation-only lazy imagery (`GraphIndex`, C18), section expansion (`SectionExpansion`, C20b), and relationship editing/unlink verification (`main.ts`, C22). C12c image reconciliation now consumes normalized presentation facts. C13 owns parser/compiler host separation; these residual consumers are not a second GraphBuilder ontology collector. C12c completes Date/Daily Notes, body URL/origin, discovery and remaining semantic metadata source collection. Compiler/parser portability remains C13. C12b therefore does not claim an atomic whole-vault source snapshot: structural, host-link and per-file ontology families have explicit independent attempt boundaries, all guarded by the existing coordinator revision.

C12b review preserved exact external Markdown target whitespace and case-sensitive file kinds through a frozen pre-extraction grammar comparison. Host-link batches share one immutable source fact/revision per source map rather than allocating those repeatedly for every target. Ontology failed/reentrant attempts and source-file changes cannot report a current finalized boundary. These family fences do not replace C14/C15's final publication/source coordination work.


## Production metadata source adoption (C12c)

`src/adapters/obsidian/metadataSourceCollector.ts` supplies Date targets/provenance, body URL occurrences and optional origins, configured presentation references and their exact host counts, semantic aliases/tags/note-type/primary-tag inputs, and physical property-name discovery. Both full and cooperative incremental graph construction consume these normalized batches; semantic no-op discovery uses the same field-only family. The compiler retains scalar/array precedence, tag/style selection, configured roles, image-link suppression, origin evidence and lifetime. Inline values retain the established parsed value-map owner; physical occurrences own discovery and only genuine source locations.

The host service contains private registry/Daily Notes/Moment compatibility reads and source-relative file resolution. Configured metadata values are narrow plain projections: unsupported objects carry a non-null marker without host references, preserving frontmatter precedence. Per-note visual count reconciliation retains no second whole-vault input map. No collector owns listeners, timers or storage. Family/source revision fences are preserved and do not constitute an atomic whole-vault snapshot. [The complete residual seam inventory](NORMALIZED_SOURCE_CONTRACT.md#c12c-completeness-and-retained-host-seams) assigns parser/compiler binding to C13, incremental publication to C14, scheduling/revisions to C15 and cache orchestration to C16. Source-boundary adoption completes C12 without declaring the legacy graph compiler portable.

## Portable parser ownership (C13a)

`src/core/parser/metadata.ts` is the single owner of K-Plex's accepted Markdown body grammar, property-reference enumeration and plain parser DTOs. It contains the self-contained synchronous worker function, the cooperative equivalent, field-name normalization and the streaming/nested property-value reference iterator. The cooperative entry point requires an explicit `{ now, yield, shouldContinue }` runtime; the portable module has no Obsidian import, browser/DOM global, default timer, Node API or storage dependency. The synchronous worker function remains closure-free when serialized with `toString()`.

`src/index/fieldParser.ts` is now a named host compatibility facade. It retains only host metadata merge/acquisition helpers, source-relative `getFirstLinkpathDest()` resolution, and the historical `parseBodyMetadataCooperative(content, shouldContinue, budgetMs)` signature that supplies the renderer clock/timer to the portable runtime. Production pure consumers (`MetadataParser` worker source, ontology/metadata collectors and direct normalization/parser callers) use the portable owner. `MetadataParseWorker` retains its legacy class name but delegates to `MetadataParser`; it owns no grammar.

The remaining production facade callers are intentionally narrow: `GraphBuilder` uses `mergeFileMetadata` until C13c moves compiler inputs; `MetadataParser` uses the cooperative runtime bridge for worker fallback; `GraphIndex`, `SectionExpansion` and `main.ts` use host-resolving `extractLinksFromValue` for lazy imagery (C18), section projection (C20b) and editing/unlink verification (C22); `SectionExpansion` also retains the cooperative bridge until C20b separates section acquisition/projection. C13b moves `RelationEvidence`/`RelationResolver` semantics and does not retire these parser compatibility calls. `parseFileMetadata` and the pure re-exports remain compatibility surface only and have no current production caller. C13c owns removal of the compiler-side metadata merge dependency. C13 remains incomplete until C13b and C13c are accepted.

## Portable evidence and resolver ownership (C13b accepted)

`src/core/graph/relations.ts` now owns only the relationship enums/roles and generic semantic relation flags needed by evidence/resolution. `RelationType` remains `DEFINED = 1`, `INFERRED = 2`; `LinkDirection` remains `TO = 1`, `FROM = 2`, `BOTH = 3`. The generic resolver target contains only an explicit semantic `path` and neighbour map. `GraphPage`, `TFile`, settings, plugin state and host materialization stay outside core; `src/types.ts` re-exports the stable enums/roles and binds the generic relation shape back to the legacy `GraphPage`.

`src/core/graph/evidence.ts` is the single owner of `RelationEvidenceStore`, declaration provenance, frontmatter precedence and evidence-to-relation application. Its copy-on-write fork/tombstone/path indexes, declaration sequence/counts, original-only storage, virtual inverse views, global/path-scoped removal and rename behavior are unchanged. Path-keyed APIs remain explicit semantic-path compatibility APIs; they do not derive paths/kinds from opaque IDs. Binding normalized source identities/files into those paths remains C13c compiler/adapter work.

`src/core/graph/resolver.ts` is the single owner of role vectors, classification, pair/full resolution and explanation decisions/reasons. Cooperative resolution takes an explicit `{ now, yield, isCurrent }` runtime and retains the 7 ms slice budget, 256-record progress cadence and batch cancellation checkpoints, with lifetime checks before and after awaited yields. Core selects no timer or browser global. `src/index/RelationEvidence.ts` is a pure re-export facade. `src/index/RelationResolver.ts` keeps the historical production signature and is the host seam that supplies `performance.now()` plus the renderer `window.setTimeout(..., 0)` yield. Existing `GraphBuilder`, `GraphIndex`, snapshot hydration and `SectionExpansion` callers therefore use the portable owner without changing publication/file binding. C14/C15 still own incremental publication and coordination; C13c still owns normalized-source-to-page/evidence compilation and host file binding. Parent C13 remains Pending until C13c acceptance.

Existing English explanation summaries/source labels and suppression text were moved unchanged and independently compared. They remain legacy user-copy debt: L01 owns catalog extraction and any structured reason/formatter separation; portability acceptance is not localization completion. C13c must preserve this API until that explicit migration.

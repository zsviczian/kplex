## Settings dispatch and authority

Semantic changes invalidate the policy revision; presentation refresh uses the existing provider, and semantic/visibility changes prepare active requested scopes. Workflow-only notifications use the presentation channel. The legacy boolean cannot bypass classification. This route does not invoke `rebuildIndex`, a full graph compiler, source invalidation, acquisition reset or contributor-catalog construction.

`GraphIndex.refreshSemanticSettings()` prepares live demand and the saved center through `ensureSemanticScope`. Current full-policy coverage can return immediately. Requested neighborhood, candidate degree and URL-title readers compile current neutral facts through the canonical semantic owner. Publication remains guarded by policy, source, host, maintenance and demand revisions. Settings do not prove physical source freshness: edits, resolver changes and uncertain sync events retain their independent maintenance paths.

## Retirement and explicit retention

Production progressive ingestion has no checkpoint-write timer, full growing-graph serialization callback or post-checkpoint pause hook. The production `persistIndexedDbSnapshot` caller supplies only the complete acceleration write. `tests/support/legacyGraphCheckpointWriter.mjs` owns the historical timer/backoff characterization. The indexing regression asserts that an ordinary progressive build makes no full-graph progress-write attempts. Legacy checkpoint readers remain necessary to reuse previously completed work; complete graph acceleration persistence remains optional.

The superseded acquisition `prepareCachedSemantics` and global `contributorDiscovery` entry points have no application callers and are already removed from the runtime; `tests/support/retiredSourcePrototypes.mjs` supplies characterization. Production acquisition creates `SourceLocalContributorDiscovery` with captured host/maintenance/generation validity. The old `SourceContributorDiscovery` class has no runtime importer; current readers use its shared contracts/helpers through type-only or specific helper imports. `CachedRequestedPairReader` and `CachedRequestedDirectOrderReader` have no production instantiation/importer; pair-capture types remain shared by current readers. Their source files and repository contributor APIs are retained for characterization and compatibility, not a live settings bootstrap. Cached semantic replay helpers remain used and are not blanket-deleted.

No store/schema migration, source/body deletion, compatibility-facade retirement, C15–C26 extraction or new cache/projection system is part of this closeout. The audit inventories retained seams rather than claiming that every historical class or repository method has been deleted.

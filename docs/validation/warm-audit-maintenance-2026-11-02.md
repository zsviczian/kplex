## Change

- Only a fresh complete eager snapshot may authenticate its source baseline through the existing closed dependency projection and bounded source-header pages. Every current Markdown source must have a supported complete head matching its native identity/stat binding. Missing/invalid/stale headers, open count journals, changed native observations and concurrent source activation reject this optional path. Normal source auditing remains the fallback.
- Accepted historical primary grammars retain the source repository's existing compatibility rules. Read-only production preflight found 8,192 supported URL-free parser-3 heads and 3,627 parser-4 heads, with no physical mismatch; requiring parser 4 for every source would have defeated the fix.
- Known local edits and authenticated referrers close through the existing local source-maintenance owner and per-file compiler at P1, yielding to canvas mutations. They do not join the paused P4 audit or overwrite either broad audit-readiness flag. The source/host/event/native receipts remain publication prerequisites. Unknown resolver/environment/topology drift retires the warm capability.
- An active audit now shows its actual note count and percentage while relationship repair is pending. A settled unavailable scope retains the existing incomplete status. Existing translated strings are reused.
- No second scheduler, source classifier, persisted store/schema, settings default or public automation signature was added. C15-C26 remain paused.

The failed report is retained, with notes unchanged and exact navigation/configuration/enablement restored. The first cold repair is now distinguished from the still-strict healthy warm-reopen assertions.

Investigation reproduced an independent derived-cache race: both edit-triggered snapshot persistence and orphan cleanup become eligible after five quiet minutes. Cleanup could classify a still-writing snapshot generation as orphaned, or select old publication roots before a new snapshot activated. Either interleaving could delete the new generation's chunks and force another rebuild. Two real Chromium IndexedDB tests failed before the fix with missing accepted snapshot pages.

Snapshot writers now retain their staged generation until success, cancellation or failure. Orphan deletion checks active/checkpoint roots inside the same transaction as deletion. Deletion is limited to 256 keys per transaction, with background yielding outside transactions, to avoid blocking foreground source writers that share the metadata store. Only disposable graph snapshot stores are reclaimed; no durable user data, source facts, schema or store migration is involved. Cancelled and failed writers release their generation so normal reclamation still works.

All four overlap/cancellation/failure cases and the nine warm admission/held-audit cases pass together. Installed Obsidian TypeScript and focused scanner checks pass. The earlier aggregate result is superseded for this additional storage change; a fresh full verification and exact-artifact native/production acceptance are required.

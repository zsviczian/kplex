## Review and implementation

Previously, graph/evidence and fingerprints could be committed for file A while semantic notification waited for the entire batch. If file B awaited or cancelled, subscribers did not receive A's publication promptly. Source fences also checked only mtime/size despite Obsidian mutating the same TFile on rename.

The synchronous `PatchFilePublisher` gives GraphIndex one per-file repository boundary: apply privately prepared graph/evidence/hot field-cache/fingerprint state, refresh affected caches/search, then notify semantic subscribers before another await. Semantic no-ops retain zero-event behavior. Captured revisions include exact path, mtime, size and current `Vault.getFileByPath(path) === file`; full-build revision maps use TFile identity. Superseded/renamed/deleted work cancels without undoing earlier committed progress or automatically requesting a full rebuild.

Main-agent review found that a publisher could retain an unapplied callback, fail the synchronous check, then publish later. The callback now expires in `finally` when the publisher returns or throws and marks consumption before application. Added real regression checks for omitted application, publisher exception, duplicate application and post-return invocation after success/failure. Commit metadata is copied and readonly-typed, not promised runtime-immutable.

No persisted schema/cache/settings/default/UI/CSS/command/localization/worker/platform or demand/storage policy changed. Full/incremental semantic classification remains the C14a shared portable compiler. Host publication is still repository-owned; coordinator and storage extraction remain C15/C16. Rollback restores publisher/revision delegates/tests with no user-data migration.

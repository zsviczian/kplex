# Localization and shortcut presentation

`src/lang/en.ts` is the source catalog and English fallback; K-Plex now bundles German (`de`), French (`fr`), Spanish (`es`), Dutch (`nl`), Japanese (`ja`), Traditional Chinese (`zh-TW`) and Russian (`ru`) catalogs. `src/lang/catalog.ts` builds each complete runtime catalog from translated message text while inheriting the source catalog's translator context, named parameters and plural count metadata. `src/lang/index.ts` validates, selects and formats the resulting catalog. Catalog keys name stable product surfaces rather than English phrases. Each source entry includes translator-facing `context`, an explicit list of named `params`, and either one `message` or a plural with a declared `countParam`. Each locale plural must supply every category returned by that locale's `Intl.PluralRules`.

Formatting is strict: unknown keys, blank/malformed entries, undeclared or missing parameters, unexpected parameters and malformed plural forms throw rather than displaying a raw key or blank text. Locale entries use the exact English key set and preserve parameter names and singular/plural shape. Parameters use `{name}` syntax and callers pass one named object, so translated sentences do not depend on English word order. Locale lookup tries an exact locale, then its base language, then English. For example, `de-DE` falls back to the bundled `de` catalog, while Traditional Chinese is registered as `zh-TW`; unsupported locales continue to fall back to English.

Obsidian language detection belongs at the host boundary. `src/adapters/obsidian/localization.ts` calls Obsidian's typed `getLanguage()` export and creates the translator. Portable feature code receives a `Translator` capability; it does not read `window.app`, browser storage or Obsidian APIs to determine language.

Shortcut presentation is separate from translated copy. `src/core/plex/shortcutPresentation.ts` owns logical shortcut specs and pure environment-aware formatting based on E00's `PresentationEnvironment`. For modifier shortcuts, the formatter shows `Command`/`Option` for macOS/iOS and `Control`/`Alt` for Windows/Android; it omits a modifier hint when the convention is unknown. It emits no hint when the action is unavailable or keyboard presence is false or unknown. This is intentional: Obsidian mobile reports hardware-keyboard presence as unknown, so K-Plex must not invent attached-keyboard detection.

The representative L00 search hint uses the existing local search handler. That handler still accepts `F4` or Ctrl/Meta+F; the displayed catalog parameter uses `F4`, which focused K-Plex search in the real desktop host check. A synthetic Command+F event was accepted by K-Plex but did not leave the field focused after Obsidian's event handling, so the UI does not advertise it. `aria-keyshortcuts` tokens elsewhere remain machine-readable standard syntax and are not localized. Host-configurable bindings must not be advertised as fixed shortcuts unless a future host adapter can provide the effective binding.

L01 migrates the legacy settings, commands, menus, dialogs, controls, notices and user-visible errors into the English catalog. Semantic relationship explanations and predicate/lens validation return structured reason/issue DTOs; UI formatters own their wording. Physical gate and Sidecar position names must also be translated before interpolation. `PlainTranslationKey` restricts label tables to keys without parameters; never widen a table to every `TranslationKey` or weaken the translator’s parameter checks.

The whole-source gate in `tests/localization.test.mjs`, implemented by `tests/support/localizationAudit.mjs`, audits TS/TSX presentation sinks outside `src/lang/`, including nested conditional/fallback/template copy, JSX text/accessibility, DOM assignments, native controls/dropdown options, command captions and declarative settings labels. Negative fixtures verify the gate rejects representative violations and permits diagnostics, stable tokens and translated expressions. This is a known-sink AST audit, not general interprocedural data-flow analysis: review variable-produced labels, helper returns and interpolation parameters as well. Catalog copy, console diagnostics, persisted compatibility constants and user/vault content have different ownership; do not translate stable data to satisfy an audit.

Relationship resolver DTOs use `frontmatter-overrides-body-ontology`, while the Obsidian predicate adapter preserves the historical English `evidence.suppressionReason` value for existing saved lenses, including substring predicates. New advanced predicates can inspect `evidence.suppressionCode` for the locale-neutral code. The compatibility value is a persisted selector contract, never display copy, and must not be translated. No settings/cache schema migration is required. Blank saved lens names remain blank data; `filter.untitledLens` supplies the display fallback.

[The L01 review report](validation/L01-2026-09-27.md) records the original English-catalog migration checks. The bundled non-English catalogs added afterward retain the same stable keys, parameters and host-boundary language selection model.

Plex-local shortcuts are now configured in **Internal hotkeys**. The native hotkey pill and delete/customize/restore icons use Obsidian classes and public `ExtraButtonComponent`; recording temporarily pushes a public `Scope`, released on completion, cancellation, blur or page teardown. macOS/iOS pills use native modifier symbols. `src/core/plex/internalHotkeys.ts` owns their action registry, default bindings, additive validation, exact modifier matching and recorder normalization. Explicit `null` disables an action; missing entries receive defaults and unknown future entries survive loading. Foreign ExcaliBrain imports do not import these workflow preferences. New `hotkeys.*` copy uses the established explicit English fallback until reviewed translations are supplied.

Search and Find use their current bindings, and the Vault search hint disappears when its binding is disabled. Concrete native scopes and DOM fallback delivery belong to each K-Plex surface and are released together on teardown. Navigation and relationship shortcuts require normal mode and bare Plex focus; editors, form controls, search fields and dialogs retain their own keys. Spatial selection consumes the current filtered/repacked projection, reveals overflow rows, and remains separate from graph-center navigation and history until Enter. Shortcut changes save workflow preferences and refresh registrations without semantic invalidation.

# Authoring a portable Facets preset or lens

This is an offline authoring instruction for a person or AI assistant. It does not install a skill, run a model, execute a script or provide CLI commands. The native **Copy AI authoring prompt** action supplies the same detailed format guidance from [`authoring.ts`](../src/core/plex/sharing/authoring.ts); every exported package carries its inert `aiContext` separately from end-user Help.

1. Read the [portable schema](PORTABLE_PRESETS.md), [Facets guide](FACETS.md), [view API](CANVAS_VIEW_API.md) and real examples. Use the one canonical [`validatePortablePackage`](../src/core/plex/sharing/validation.ts) for output. Do not create an AI-specific settings store or validator.
2. Ask what explicit local metadata classifies the notes. Choose one source. Keep 3–12 stable category IDs and a fixed ordered list. Prefer simple documented values; do not infer importance, psychology, causal evidence or note content using scores or prose analysis. Define intentional canonical assignments separately from aliases.
3. Generate a useful preset-specific `helpMarkdown`: purpose, actual category/rule meanings, concrete YAML matching the chosen fields/values, practical use and limits. Include incomplete/conflicting metadata behavior. Avoid generic promotional text or features the plugin does not provide. Keep source under 4,096 characters, with no HTML/embeds/remote images/executable examples. `helpSourceLocale` is optional; Help is distinct from the long AI instruction in `aiContext`.
4. Choose layout and presentation defaults. Quadrants needs four categories. Concentric rectangles are disjoint bands around a single centered focus; thickness controls and bounded top-strip cards are intentional. Linear layouts support cardinal focus anchors, reversal and decorative workflow rails. Automatic columns follow measured usable width; do not invent a `columns` field. Combined Diagnostics defaults on; each status chip retains its meaning. Never turn a decorative guide into canonical relationship evidence or a clearing drop target.
5. Use portable theme/palette identities or literal colors. Include only referenced literal palette pairs. Include optional lenses only if the user explicitly chooses them. Export no enabled state, private paths/note contents, credentials, device preferences, ontology/index policy, navigation/history/pins or editor state. Ask the human to review any detected private selectors rather than redacting and changing their meaning.
6. For rules/lenses, use the existing grammar: `note.state == "draft"`, `note.priority >= 3`, `this.phase == "wood" && note.phase == "metal"`, `edge.role == "parent"`. `note` is the candidate; `this` is the current focused note, with fixed built-ins reserved. Availability-aware reads keep missing metadata unknown under negation. Strict equality preserves type/case; `.equals()` compares text without case. Edge/evidence contexts need canonical recorded relationships. No arithmetic, JavaScript, SQL, Dataview or fetch. Import never grants note-write authority.
7. Produce the version-1 envelope and run canonical validation. Unknown fields or future versions must fail safely. Keep it concise: the package limit is larger than the installed library limit, so the actual save can refuse a package that will not fit without changing existing settings.
8. Preview in the native import dialog. Check exact categories/colors/rules/help, target/collision decisions and optional dependencies. New dependencies arrive unchecked and imported lenses stay disabled. Test Cancel, failure and stale-preview behavior. Do not claim an import has been saved, activated or validated on a native device solely because JSON was generated.

Arbitrary focused-note properties such as `this.phase` are available in Facets' opt-in availability-aware rules. Ordinary lenses retain the existing fixed `this` attributes (for example `this.name`); do not assume that a custom focused-note property works in a standalone lens. `note` still addresses candidate properties.

See [example packages](../tests/fixtures/portable-presets/README.md). The validator is host-free and takes JSON text or programmatic JSON data; it returns structured issues or a detached validated package. Future CLI/API integrations must call it and then the same guarded settings owner. This delivery implements no AI network calls or automation.
